INTRODUCTION						*jin-introduction*

vim-jin runs jj and shows what jj prints in buffers. It is meant for
watching and following a repository while you, or an agent, work on it.

	:Jin new
	:Jin ++wait describe -m "feat: add parser"

Every vim-jin buffer is read-only and tied to no file; its name starts with
"jin://" and records everything needed to read it again.

=============================================================================
REQUIREMENTS						*jin-requirements*

- jj on $PATH.
- Neovim 0.10 or later, or Vim 9.0.0067 or later built with |+lua|.

=============================================================================
COMMANDS						*jin-commands*

Arguments are split the way a POSIX shell splits them, so a command copied
from a terminal means the same here: white space separates them, single
quotes take everything literally, double quotes everything but an escaped
`"` or `\`, and outside quotes a backslash escapes the next character. `|`
does not end the command, so a revset such as `root()|@` reaches jj intact.
No variable, glob or `~` is expanded.

							*jin-%*
A bare `%` stands for the file of the current buffer, relative to its
workspace root.

Every command runs jj in the workspace of the current buffer, falling back
to the workspace of the current directory, or, outside any workspace, in the
current directory itself. All of them complete their arguments with what
the installed jj offers.

							*:Jin*
:Jin [++option...] [{args}]
	Run `jj {args}` and echo what it printed, in |hl-ErrorMsg| when it
	fails. jj runs in the background, and |User_JinCommandPost| fires
	once it has finished.

	++wait		Return only after jj has finished.

							*:JinBuffer*
:JinBuffer[!] [++option...] [{args}]
	Open a buffer showing what `jj {args}` prints, in jj's own colors.
	The buffer opens at once and fills when jj answers. Opening one
	already open switches to it; with [!] it reads jj again first.
	`:edit` reads jj again too.

	++opener={opener}	Open the buffer with {opener} (`split`,
				`vsplit`, `tabedit`, ...) instead of
				|:edit|. Modifiers such as |:botright|
				apply as well.
	++monochrome		Ask jj for output without colors.
	++filetype={filetype}	Set the filetype of the buffer.

=============================================================================
VARIABLES						*jin-variables*

							*b:jin_title*
b:jin_title		A short title of a vim-jin buffer, such as
			"jj log -r @-", for a statusline or a tabline in place
			of its long name:
>vim
	set statusline=%{get(b:,'jin_title',expand('%'))}
<
=============================================================================
EVENTS							*jin-events*

						*User_JinCommandPost*
JinCommandPost		After |:Jin| or |jin.command()| has run jj,
			successfully or not.

=============================================================================
LUA API							*jin-lua*

`require("jin")` works in Neovim and in Vim built with |+lua|. Each function
runs jj in the workspace of `opts.cwd` when given, or else as |:Jin| would.

						*jin.jj()*
jin.jj({argv} [, {opts} [, {on_exit}]])
	Run jj and return `{ code, stdout, stderr }`, echoing nothing and
	firing no event. With {on_exit}, return at once and call it with
	the result. `opts.color` asks for ANSI colors, `opts.env` adds
	environment variables.

						*jin.command()*
jin.command({argv} [, {opts} [, {on_exit}]])
	Do what |:Jin| does. `opts.wait` stands for `++wait`.

						*jin.buffer()*
jin.buffer({argv} [, {opts}])
	Do what |:JinBuffer| does and return the buffer number. `opts` takes
	`opener`, `monochrome`, `filetype`, `mods` and `reload` (the [!]).

						*jin.root()*
jin.root([{path}])
	The root of the workspace holding {path}, or of the current buffer
	or directory; nil outside any workspace.
